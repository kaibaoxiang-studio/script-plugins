# Excel 输出与验收

本地 `0.3.2` 使用 `workflow.py export/finalize` 作为生成与交付入口。底层 `build_xlsx.py` 会自动重开保存文件验收，通过后才替换工作簿；四表实际视觉检查完成后仍须 finalize 绑定交付哈希。以下模板与排序规则沿用 v0.1.1，执行阶段、台账参数和其他后端交付方式见 [执行契约](execution_contract.md)。

## 统一模板

`scripts/export_contract.py` 定义四张表的固定表头、列序、列宽、合并范围和样式。人物保留“出场次数”；场次总表保持原有十一列，末尾追加“原文人物行”“逐场备注”，不以备注替代“待处理”覆盖检查或“校验确认”。缺失集标题留空，不补造。

人物与道具每状态一行，场景每子场景一行；同一资产的基础列合并。资产分组整组使用同一底色，相邻资产交替白色/浅蓝色；不是状态行交替。标题行深蓝白字、居中，细灰边框，冻结 C2，完整范围自动筛选。四张表所有单元格统一水平、垂直居中并自动换行；正文及表头 Arial 10，不缩小字号掩盖溢出。

人物阶段按剧本呈现顺序、行号、行内位置逐次展示，现实→闪回→现实不归为一个块。同状态再次使用仍是一行，场次去重，但阶段记录不丢失。允许省略可无歧义还原的重复“本体”或同状态名，并在该单元格说明约定；只合并相邻且相同的备注。不按时间线或相同句子把远处记录拖到前面。

场景备注保留所有状态名称、场次、描述、依据和状态 note；场次总表按实际状态查找，不能用子场景名称代替状态。人物逐场问题、道具局部指代问题均须出现在对应场次的备注。未知外观与原文矛盾是信息缺口，不伪装成已确认警告或已完成设计。

## 两种导出后端

- 标准 `build_xlsx.py` 直接写 Excel。
- 运行环境指定其他 Excel 后端时，先 `build_xlsx.py ... --export-spec <计划.json>`，仅将计划渲染为工作簿；禁止自行重写提取、排序、表头和分组规则。

列宽和行高由计划按中英文字符、显式换行及合并区域计算。行高没有固定 150 点截断；超过 Excel 409 点限制时阻止生成，先保序压缩重复项。仍无法容纳时说明具体受影响字段并请求展示调整，不删记录、不缩字号、不隐藏必需列。

若后端缺少自动筛选，可在导出后运行 `scripts/add_native_filters.py <xlsx> <计划.json>`：该补丁只设置原生筛选范围，不修改数据、字体、合并或列结构；仍须完整验收。合并基础列只在组首存值，筛选状态/场次后组首可能隐藏；筛选适合定位，不能承诺 Excel 自由排序会保持资产组，应重新按输入生成排序。人工抽查至少实际筛选状态或场次一次。

## 验收

1. `--check` 校验提取数据；不能证明词语是特指异称或造型是稳定基础特征，须人工核对。
2. `check_workbook.py <scenes> <assets> <xlsx>` 从当前输入重新生成期望值，只读检查已保存文件的四表、所有单元格、排序、状态场次、备注、合并、分组底色、字体、边框、换行、列宽行高、冻结和筛选；不能拿导出计划本身当独立正确性证明。
3. 正常缩放视觉检查每张表：编号名称易找、同资产边界连续、状态阅读不串行、长文本无截断、短行无统一大留白。检查长备注行和完整人物合并组，预览裁剪不能截断合并区域后误报空白。
4. 运行回归测试，至少覆盖同场切换/闪回返回、非数字场次顺序、状态 note 导出、局部泛称和故意损坏的工作簿。

正式输出仅资产 JSON 与最终 Excel；计划、预览、验收日志及备份属于工作文件。统计区分真实状态版本与子场景展示行数。
