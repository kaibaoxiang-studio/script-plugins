# 人物外观状态与逐场归属

## 判定顺序

人物身份 → 实际出镜 → 原文外观事实 → 时间线与阶段 → 可复用状态 → 派生场次。

不要先列几个状态再把场次分进去。状态 ID 表示美术可复用的造型版本，出场记录 ID 表示这个版本在具体画面阶段的使用。白裙 → 婚纱 → 白裙可以引用 S01 → S02 → S01，而不是新增第三套白裙。

Excel 人物表按人物出现场次的去重数量降序排列，次数相同按首次实际出场位置排序；人物内部状态按该版本首次实际出现的场次、行号和字符位置排序。重复使用的版本以首次出现为准。人物和状态 ID 不因展示排序重新编号；同一人物状态保持连续分组。场次取剧本呈现顺序，闪回不按故事年代提前排列。

## 什么需要记录或拆状态

状态的六类 `visual` 字段为年龄、服装、形态、妆发、伤势和污损。既有原文明示，又需要独立制作/外观组件的变化可拆状态：换装、童年、狐形、兽耳版本、明显包扎、染血等。以画面制作需求判断，不以必须全身改变、贯穿整场或“完整新造型”作为门槛。

纯表情、动作、眼神情绪、灯光及瞬时后期发光不拆造型状态。披风加穿、小伤、兽耳等先记录事实；仅是可直接挂接的现成组件、无需新版本时可保持原状态，在该 `appearance.segment` 说明可见变化。是否需制作新版本拿不准时将具体场次和变化写入 note，不把不确定性伪装成已确认造型。

每个已知状态必须有原文证据。人物首次出现未写外观时用“外观未说明”状态，不能推测服装款式、身高、发色或“无配饰”。已确认外观中缺失的字段也写未说明。人物基础设定只保留跨版本稳定且有依据的特征；童年/成年、形态、伤势等不能固化进所有状态。

人物小传中的“后来/后期”外观也归对应版本，不能因它写在小传就放进稳定基础设定。已知状态用实际外观命名，场景用途或事件名不能代替造型特征。

description 用已有确定信息组织成可读视觉描述；未知说明即可，不要求凑齐具体细节或达到字数。设计推断须与提取事实分开，在 note 写清推断依据、适用版本和待确认内容，不能据此创建或分配已知状态。

## 场次归属与继承

- 沿剧本呈现顺序逐场记录，不把场次号当成故事时间。每场行号按 `scenes.json` 的 `lines` 数组从 1 开始。
- `timeline` 标识故事连续段，如“现实·连续段1”“童年闪回·事件A”。同一时间段名称只能在确有连续性时复用；时间跳跃后无法确认外观时新建连续段并 reset。场景日夜本身不代表换装，也不证明故事连续。
- `instance` 为画面实体，一般“本体”。镜像、分身同框且不同造型时分别标识，必须有原文依据；不能为绕过区间重叠而随意拆实体。
- `basis=explicit`：本阶段原文明示该版本，evidence_refs 指向本阶段依据。重新穿回旧衣服也用 explicit，复用旧 state_id。
- `basis=inherited`：已确认故事连续且无外观变化，from 指向同时间线同实体最近的一条出场记录，状态必须一致；不能跨 reset 或从未说明记录继承已知状态。跨集可以继承，必须先确认连续性。`continuity` 必填，说明依据哪些剧情动作或时间信息确认连续，不可只写“没有换装”。
- `basis=unspecified`：无法确认当前外观，引用 basis 同为 unspecified 的状态，相关外观字段均写“未说明”。这表示信息缺失，不能被当成“角色真的换了衣服”的证据；在 note 写具体缺失问题。
- `boundary=reset`：时间线/实体首次记录、时间跳跃、重新开始或连续性无法确认。该阶段要重新找明示依据，缺失则 unspecified。已有连续段内可用 continuous。
- 离场后没有持续画面，不把状态填进缺席场次。人物行漏写但动作明确出镜可用 action 证据；名字被提及、VO/OS、照片/投影等要结合画面语义判读，不能因搜索命中就加入本体出场。
- 服装、形态、年龄、伤势、妆发、污损分别跟踪。变回人形不自动治愈、换衣不自动消伤；只保留有连续性支持的旧特征，新证据优先覆盖对应字段。

## 同场多阶段

用 `start_line`/`end_line` 定位一个外观版本实际可用的画面阶段，不要求填满全场：人物离场或只在对白中被提及时可留空区间。人物行在列但正文没有可划分段落时，整场作为阶段；原文完全没有 lines 时两者为 0。

同一时间线同一实体的阶段不能重叠。一场先白裙、后染血、再变狐形，按三个原文区间记录。同场回到之前版本，再加一次 appearance 引用旧状态；该状态的 scenes 最后去重，只出现一次场次号。

**同一动作行内连续变化**时可设置 `start_offset`/`end_offset`，表示该行 text 内从 0 开始的字符位置，结束位置不包含在区间内。默认开始 0、结束为该行文字长度。将行内各阶段划成相邻但不重叠的字符区间；跨行记录的 offset 分别作用于首行和末行。只在原文能确定先后时这样拆，不能凭空补出转变前状态。

## JSON 骨架

顶层仍只有 characters、scenes、props。人物包含 appearances 和 change_reviews；不把 events/costumes/effects 另建顶层资产类别。

下面是格式示例，实际引文必须换成输入原文。假设 1-1 的 L1 写“莱拉穿白裙入场”，1-2 有连续剧情但未重复描写服装：

```json
{
  "id": "CHR-001",
  "name": "莱拉",
  "aliases": [],
  "role": "主角",
  "description": "基础生理特征剧本未说明，待设计确认。",
  "note": "",
  "states": [
    {
      "id": "S01",
      "name": "白裙",
      "basis": "explicit",
      "visual": {
        "age": "未说明",
        "costume": "白裙",
        "form": "未说明",
        "hair_makeup": "未说明",
        "injury": "未说明",
        "stains": "未说明"
      },
      "description": "身穿白裙；年龄、形态、妆发、伤势和污损情况剧本未说明。",
      "evidence_refs": [{"scene_id": "1-1", "line": 1, "quote": "莱拉穿白裙入场"}],
      "scenes": [],
      "evidence": "",
      "note": "其他造型细节待设计确认。"
    }
  ],
  "appearances": [
    {
      "id": "A001",
      "scene_id": "1-1",
      "start_line": 1,
      "end_line": 1,
      "segment": "白裙入场",
      "timeline": "现实·连续段1",
      "instance": "本体",
      "state_id": "S01",
      "boundary": "reset",
      "basis": "explicit",
      "from": null,
      "presence": {"kind": "header", "refs": []},
      "evidence_refs": [{"scene_id": "1-1", "line": 1, "quote": "莱拉穿白裙入场"}],
      "note": ""
    },
    {
      "id": "A002",
      "scene_id": "1-2",
      "start_line": 1,
      "end_line": 1,
      "segment": "连续行动，沿用白裙",
      "timeline": "现实·连续段1",
      "instance": "本体",
      "state_id": "S01",
      "boundary": "continuous",
      "basis": "inherited",
      "from": "A001",
      "continuity": "上场人物走出房门，本场紧接走入相邻走廊；无故事时间跳跃。",
      "presence": {"kind": "header", "refs": []},
      "evidence_refs": [],
      "note": ""
    }
  ],
  "change_reviews": []
}
```

示例中的空 change_reviews 只是留出字段位置；含候选的实际剧本必须按下节填完，不能直接把空数组交付。

状态 evidence_refs 的每条引文必须也出现在该状态某次 explicit appearance 的 evidence_refs 中，便于核对版本来源。可收录多个场次的补充/再次出现证据。`evidence` 为展示文字，`scenes` 为去重场次，两者由同步脚本生成。

人物行漏写时，presence 改为：

```json
{"kind": "action", "refs": [{"scene_id": "1-1", "line": 1, "quote": "莱拉穿白裙入场"}]}
```

出镜证据须在本阶段动作行，且语义上确实是此人物出镜。借由名字搜索到的他人回忆、计划或台词提及不符合。

未知状态用 `basis: "unspecified"`、六类 visual 全为“未说明”、`evidence_refs: []`。appearance 的 evidence_refs 也可为空，但必须有合法出镜依据，并在 note 标明未确定的原因。不得为此添加原文不存在的“常服”。

## 校验与迁移

新提取必须提供逐场记录和所有变化候选的复核结果；旧 assets.json 仍可读取，但缺 appearances 或缺候选复核将被校验阻止。不要从旧 scenes 列表机械生成“连续沿用”，那会固化旧错误。逐人读取全剧原文，重建出现阶段、变化和连续性，再同步派生字段。

`--sync-character-scenes` 先校验记录，再按剧本顺序写回状态的 scenes 与 evidence。`--check` 进一步要求派生字段与记录完全一致，并执行全资产覆盖校验。未通过时不写 Excel。

程序能发现无效引文、重复引用、错场、区间重叠、继承链断裂、字段矛盾及未复核的关键词候选。它不能判定“这句话真的描述了此人此造型”，也不能找到关键词表之外的所有变化。主 agent 仍须逐条回查变化边界，尤其同场转换、闪回/梦境、恢复与反复使用版本。独立 read helper 提供原文候选，不自动推断状态。

## 独立变化复核 change_reviews

运行 `show_character.py <scenes.json> <人物名> [别名 ...] --changes`。扫描原文动作行，不依赖已填的状态。人物行在列时也扫描代词/他人动作，避免只搜索姓名漏掉变化；这会产生误报，必须人工判读。纯对白不自动作为出镜变化候选；仍应在全文阅读时结合画面核实。

每个候选包含 candidate_id、完整原文 source、命中 cue 和字符区间。同一行内不同线索分别产生候选；记录 source 和编号原样复制，不手编编号。候选编号绑定场次、行号、命中位置和原文摘要，原文更改后须重新复核。

人物下每条复核记录格式为：

```json
{
  "candidate_id": "从候选输出原样复制",
  "source": {"scene_id": "1-1", "line": 1, "quote": "该行完整原文"},
  "decision": "recorded",
  "appearance_ids": ["A001"],
  "reason": "该线索对应本阶段已明确呈现的白裙外观。"
}
```

- recorded：初始外观、变化或再次确认已有造型；关联覆盖候选位置的 appearance，该阶段必须 explicit，且 evidence_refs 包含此线索。
- component：局部现成组件变化，不拆造型版本；关联实际出现阶段，reason 写明如何呈现和不拆的原因。
- uncertain：变化或制作需求未能确定；关联出现阶段，并在 appearance.note 记录具体待确认问题。该备注会按场次、阶段、时间线导出到人物表和场次总表。
- not_visible：描述计划、回忆或假想而未呈现画面；appearance_ids 为空，说明排除理由。
- other_character：候选实际描述其他人物；appearance_ids 为空，写清对应人物及判断依据。
- nonvisual：如“散发气势”等词误命中，或纯动作/特效；appearance_ids 为空，说明不涉及造型版本。

所有决策均必须有非空 reason；不能用同一句模板批量掩盖未判读的候选。未复核、重复、过期、错误关联都阻止同步/交付。通过校验只代表已覆盖扫描到的线索和可计算约束，不代表自动证明语义或完整性。
