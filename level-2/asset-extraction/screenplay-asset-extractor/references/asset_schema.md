# 资产判定规则与 assets.json 格式

## 资产范围

| 类别 | 收录 | 不收录/归入其他类别 |
| --- | --- | --- |
| 人物 | 人物行出场，以及动作原文明示有画面的角色，含群演 | 只在台词里被提到而未出镜的人；VO/OS 须结合画面判读 |
| 场景 | 需要设计或搭建的空间 | 同一空间异称合并；可共用搭建的区域作为子场景 |
| 道具 | 需单独制作的可移动剧情物件、可独立出镜的专属物品、被特写或有重要状态变化的物品 | 固定陈设归场景；日常服装归人物；无特写或剧情作用的普通餐具食物不独立列 |

被拿起、递交、使用，反复出现且有象征意义，或会破坏/染血的剧情物件一般作为道具。披风、王冠、尾戒等穿戴物按实际用途判断：作为造型的一部分归人物；被摘下、递交、掉落且独立出镜时可同时建立道具资产。物品与人物的状态不应互相替代。

王座、火盆、床、浴池、烛台、地毯、书架及建筑元素通常归场景陈设。只录入原文明示的陈设，不因空间名称补出不存在的王座或装饰。

## 状态判定

**人物全部状态规则、结构和场次分配见 [character_states.md](character_states.md)。该文件是人物规则唯一来源。** 不使用“必须完整换装/大面积变化/贯穿整场”等旧门槛；人物需先写 appearances，再同步 scenes。

场景和道具的状态仍按需要重新制作或明显修改的持续外观变化判断：

| 类别 | 新状态 | 不拆状态 |
| --- | --- | --- |
| 场景 | 大面积坍塌、焚毁、水淹、婚礼布置、战后废墟等搭建变化 | 日夜、内外、灯光、雾气、烛火变色、窗帘拉开、个别摆设调整 |
| 道具 | 破损、断裂、大面积染血等持续外观变化 | 更换持有人、换位置、瞬间发光或冒烟 |

每个资产至少有一个状态；场景有完整 subscenes 时可由其承担场次覆盖。初始状态叫“常态”或实际外观名称。新状态 evidence 引用原文变化短句和场次号。场景用途、婚礼情节、下雨等信息不能替代人物换装依据。

## 描述与未知信息

description 描述视觉外观，evidence 保存原文依据。不要把“走上台、接过奖杯、昏倒”等情节动作拼成外观描述。

- 人物固定特征与各版本描述按 character_states.md 填写。
- 场景基础描述包含原文确定的尺度、材质、布局、陈设、标志性装饰；状态描述说明实际布置/破坏变化。
- 道具描述包含原文确定的材质、颜色、尺寸/形态、标记、功能，以及对应状态的破损或染血部位。

没有明确说明的视觉细节写“剧本未说明，待设计确认”。合理设计推断只能补充已有资产，写入 note 并标明依据和适用范围，不能被当成原文明示，也不能据此新增资产或人物状态。不为凑描述字数添加身高、材质、配饰和具体陈设。

note 记录需要人工确认的内容：视觉细节缺失、时间连续性不明、疑似同一道具、可能需要补充设计的具体场次。确定的提取判断不重复写入 note；人物逐场归属判断记录在 appearance 的 basis/from 等结构化字段。备注中出现“因为”等词本身不构成错误。

人物 appearances[].note 会带具体场次、阶段和时间线汇入人物表备注，同时出现在场次总表。不要仅依赖资产级 note 表达某一场的局部问题。变化候选的判读过程写 change_reviews.reason；需人工确认的问题还要放到相应 appearance.note。

## 合并、角色和编号

- 人物同一身份的名字/称谓写入 name 或 aliases；别名不能同时指向不同人物。年龄版本一般在同一人物下拆状态，原文确实是独立角色时分开。替身、分身、镜像须按身份与实际画面判断。
- 角色类别：主角为剧情核心；主要配角有独立剧情线或重要影响；配角有台词、明确设定或关键剧情作用；群演为无台词的群体角色。有台词的“侍从1”“守卫2”等不能归群演，但不将主角/主要配角降为配角。
- 道具按实物身份合并异称：有明确同义说明、连续交接或独特特征一致的证据时，归入一个 ID，原文特指称呼写 aliases 并附 alias_evidence。泛称、代词按 mentions 的局部上下文定位；同名不同物以归属/形态等原文区别限定主名。疑似同物但缺乏依据时分开，以 identity_relations 和 note 记录待确认。完整规则见 [prop_identity.md](prop_identity.md)。
- 人物 `CHR-001`、场景 `SCN-001`、道具 `PRP-001` 按首次出场编号。
- 状态 `S01`、`S02` 在资产内唯一；展示拼为 `CHR-001-S01`。人物出场记录 `A001` 等在人物内唯一。

## 场景层级

主场景是可独立设计/搭建的完整空间；子场景是视觉相连、能共用搭建的区域或视角。例如大厅与其侧廊可为主子结构，书房与森林一般独立。

主场景用常见简称，全称写 aliases；子场景名可用“侧廊”“门口”。主场景的 int_ext 和 times 必填，从其所有实际场次汇总，不能只取某一个子场景的值。subscenes 的场次并集应与主场景状态的场次并集一致。

```json
{
  "id": "SCN-001",
  "name": "黑曜大厅",
  "aliases": ["暴风尖塔王宫黑曜大厅"],
  "int_ext": "内",
  "times": ["日", "夜"],
  "description": "仅填写输入原文明示的空间与陈设。",
  "note": "",
  "subscenes": [
    {"name": "主厅", "description": "原文空间特征", "scenes": ["1-1"]},
    {"name": "侧廊", "description": "原文空间特征", "scenes": ["2-1"]}
  ],
  "states": [
    {"id": "S01", "name": "常态", "description": "原文布置", "scenes": ["1-1", "2-1"], "evidence": "对应场次及原文", "note": ""}
  ]
}
```

没有子区域时 subscenes 省略或为空，按 states 收录场次。以上只是格式例子，不代表这些场次或陈设存在于输入剧本。

## JSON 顶层格式

顶层仅 characters、scenes、props 三个数组。人物的完整 states/appearances/change_reviews 骨架见 character_states.md；道具的 alias_evidence/mentions/identity_relations 骨架见 prop_identity.md，不能只照本节简化示例交付。具体警告确认保存在独立文件，格式和授权要求见 [warning_approvals.md](warning_approvals.md)。

```json
{
  "characters": [],
  "scenes": [],
  "props": [
    {
      "id": "PRP-001",
      "name": "匕首",
      "aliases": [],
      "owner": "实际归属人物，无则空字符串",
      "description": "原文明示的形态、颜色等外观",
      "note": "",
      "alias_evidence": [],
      "mentions": [],
      "source_name": "匕首",
      "identity_relations": [],
      "states": [
        {"id": "S01", "name": "常态", "description": "当前外观", "scenes": ["1-1"], "evidence": "1-1：输入原文短句", "note": ""}
      ]
    }
  ]
}
```

scenes 中所有场次号必须真实存在于解析输出。道具 owner 是主要使用者，临时转手不自动拆状态。

## Excel 格式

实际模板及后端适配/验收规则见 [excel_output.md](excel_output.md)，不得自行另写列序和样式。

保留人物、场景、道具、场次总表四个 sheet。

- 人物与道具：每状态一行，资产 ID、名称、别名、类别/归属和基础描述合并。状态列显示状态 ID、名称、描述、出现场次、原文依据、备注。
- 人物分组按出现场次数降序排列，统计 appearances 场次号的去重数量；同场多个状态/阶段/实体只计一次。次数相同按首次实际出场位置排列，同位置稳定保留原顺序。各人物的状态按首次使用场次排列，同场按阶段位置排列，反复使用的状态仍只占一行。场次取解析剧本的呈现顺序，ID 保持首次编号，不随导出排序改变。
- 人物新增“场次·阶段·时间线”列，显示该状态各次使用的原文区间、时间线、实体及阶段说明。
- 道具新增“异称与身份依据”列；同一道具一组、破损等状态逐行。场次总表展示统一主名与实际原文词，转手时仍指向同一 ID。道具场次从 mentions 中 visible 的记录按剧本顺序去重生成，reference 不计出场。
- 场景：主子场景展开，显示场景 ID、主/子名称、内外、时间、子场景描述、场次及备注。
- 场次总表：每场一行，人物状态按逐场记录显示原文阶段、时间线、实体及明示/沿用/未说明，状态转换按原文顺序可回查，逐场备注同步展示。保留现有覆盖检查列；“校验确认”列显示用户已确认的具体警告和依据。未经确认的待处理内容阻止交付。

人物派生 scenes 不含重复场次，同场使用同一版本多次只列一次；具体先后仍保留在 appearances 和阶段展示中。
