# 1.0.2 资产提取修补与验证

日期：2026-10-27。项目补丁版本 1.0.2，资产表组件 0.1.1，包内 DOCX Skill 0.1.2；其余组件版本不变。

## 触发问题与修改

测试反馈中，道具表为零，人物层级全部留空。原 JSON 入口的 prepare 仅建立基础底稿，之后应由 Agent 通读内容补齐；旧 finalize 未检查此步骤是否完成。DOCX 对已有道具身份的检查，也无法证明空道具表已经过逐场提取。

两入口现在都要求逐场原文审核、实际资产引用和类别结论，并绑定来源及资产快照哈希。JSON 覆盖每个内容块，DOCX 覆盖每行。漏场、漏块/行、过期数据和缺失结论均阻止正式导出。没有道具或独立特效可以是合法结果，不设置数量必须大于零的门槛。

持有人、材质、尺寸或状态变化未写明，不作为拒收实际出镜道具的理由。未知字段留白，身份疑点另行记录。

真实调用还暴露同名 Skill 解析到旧本机缓存的问题：有道具数量，但没有新版审核记录。组件派发现在明确精确 Skill 文件和插件根；Harness 收尾还运行当前包的 verify_delivery.py，复核工作文件、正式资产、疑点及返回计数，不能用旧格式交付宣告新版成功。内部派发只用经服务器确认的临时会话，不恢复持久聊天。

构建器保留 DOCX Skill 与输入路由，补全锁定 DOCX 依赖；重建不会退回只有 JSON 的旧包。

## 真实能力调用

DOCX：通过精确新 Skill 路径，以临时 CLI 调用完成两份合成输入的解析、通读、提取、审核、同步、正式检查、Excel 导出与保存后验收。拿钥匙并递手机的小样得到 2 人物、1 场景、2 道具；空房间空镜得到 0 人物、1 场景、0 道具。两个 assets 都包含有效审核；两次数据检查和两次工作簿检查均为零错误、零未确认警告。模型产物未由外部人工补写。首次传输重试后 CLI 自动回退 HTTP，没有修改用户模型配置。

JSON：明确源路径与收尾复核修正后的两份真实 Harness 小样均通过。拿取/连续交接小样为 2 人物、1 场景、2 道具、2 场；纯站立小样为 1 人物、1 场景、0 道具、1 场。逐块审核、输出数据、实际计数和收尾复核全部通过。此前误用旧缓存的两次调用不计为通过证据。脱敏调用结果、时长及输出哈希见 [本次记录](validation/asset-extraction-1.0.2.json)，包核验见本次发布清单。

## 边界与兼容

审核记录能验证覆盖、引用及快照一致性，不能数学证明每句语义判断正确。没有重新提取外部反馈的完整原剧本，也没有据 Excel 编造完整遗漏清单；已有历史交付物仍可读取。旧工作文件要回查原文补审核后才能新导出。

DOCX 工作簿已做程序验收，应用正常缩放下的人工目视与实际筛选交互未执行。此补丁没有新增图片审美验收。真实原稿、本机路径、账号信息及原始调用日志不随公开镜像分发。
