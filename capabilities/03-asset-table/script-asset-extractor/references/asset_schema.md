# 资产判定规则与 assets.json 格式

## 一、什么算资产

| 类别 | 收录                                                                                                                                                                                     | 不收录                                                                                                                                                                 |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 人物 | 人物行中出现的所有角色，包括群演类（黑甲守卫、侍女）；只在动作行出现但有画面的角色也要收                                                                                                 | 只在台词里被提到、没有出镜的人                                                                                                                                         |
| 场景 | 每个需要单独搭建或设计的空间                                                                                                                                                             | 同一空间的不同叫法（合并成一个）                                                                                                                                       |
| 道具 | **需要单独制作、可移动、推动剧情**的物件：武器（匕首、长鞭）、关键物品（狐族尾戒、血契卷轴）、人物专属物品（披肩、王冠）、**会被破坏或状态变化**的物品（蜜糕盘从完整到破碎） | **场景固定陈设**（火盆、王座、烛台、地毯、书架、床、浴池）；**普通餐具食物**（汤盅、银盘、蛋糕，除非有特写或推动剧情）；人物身上的服装（服装归入人物状态） |

### 道具 vs 场景陈设的判定标准

**独立道具**（单独列为资产）：

- ✅ 被角色**拿起、递交、使用**（匕首、长鞭、卷轴）
- ✅ 有**特写镜头**或**推动剧情**（狐族尾戒、血契、金狐簪）
- ✅ **人物专属武器或配饰**，可以脱离人物身体单独出镜（匕首、长剑、尾戒、发簪）
- ✅ **状态会变化**（药瓶破碎、卷轴染血）
- ✅ **反复出现**且有象征意义（屠龙匕首、血契）

**场景陈设**（写在场景 description 里）：

- ❌ **固定在场景中**，无法移动或很少移动（王座、火盆、烛台、书架、床、浴池、壁炉）
- ❌ **装饰性物品**，无剧情作用（地毯、窗帘、挂画、花瓶）
- ❌ **普通餐具和食物**，无特写（汤盅、银盘、酒杯、蛋糕）
- ❌ **建筑元素**（门、窗、柱子、台阶）

**人物状态**（写在人物状态描述里）：

- ❌ **披肩、披风、斗篷等穿戴物**，作为服装的一部分（除非该物品可以脱离人物单独出镜，如"披风掉落在地"且有特写）
- ❌ **头冠、腰带、项链等常戴配饰**，除非有单独特写或被摘下递交

拿不准时：问"这个东西会脱离人物身体单独出镜吗？"、"去掉这个东西，剧情还能推进吗？"如果答案都是否，就归入人物状态或场景陈设。

## 二、什么算新状态（核心规则）

**唯一标准**：需要美术部门完整设计一套新造型、重新制作或大幅修改现有资产的，才算新状态。

| 类别 | 算新状态                                                                                                                                                                                 | 不算新状态                                                                                                                                                                                                                      |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 人物 | • 完整换装（白裙→婚纱，不只是加件披风）• 年龄段变化（童年/成年）• 大面积持续性伤势或血污（全身染血、胸口缠纱布）• 持续的非人形态（化为狐形贯穿整场）• 完全不同的妆造或整体造型改变 | • 表情、动作、情绪• 发型微调、衣服被拉扯或局部脏污• 轻微脸色变化（苍白→泛红）• **瞬间的特效或形态显现**（龙纹闪现、狐耳一闪而现、眼睛发光一下）• 只是披了件外套/披风，底下衣服没变• 局部小伤（划破手臂、嘴角流血） |
| 场景 | • 被大面积破坏（坍塌、焚毁、水淹）• 布置完全改变（婚礼装饰、战后废墟）                                                                                                                 | • 日/夜、内/外、灯光氛围（这些在场次总表体现）• 烛火变色、雾气弥漫等特效• 摆设小改（多了个酒杯、窗帘拉开）                                                                                                                   |
| 道具 | • 破损、断裂、大面积沾血等**持续性**外观变化                                                                                                                                      | • 被拿在不同人手里、换了位置• 瞬间发光、冒烟等特效                                                                                                                                                                            |

### 特别强调：瞬间特效 ≠ 新状态

以下这些**不拆状态**，在常态的状态描述或基础设定里提一句即可：

- "狐耳一闪而现" "龙纹浮起" "眼底闪过红光" ——瞬间显现，不是持续造型
- "浴室中泡在水中" ——环境变化，不是人物造型变化
- "烛火齐齐变黑" ——场景特效，不改变场景搭建

拿不准时：问自己"美术需要重新做一套完整造型吗？"。如果只是后期特效、化妆微调、或加件外套，**不拆**。在状态的 `note` 里写「某某场有XX特殊表现」即可。

每个资产至少有一个状态。第一个状态叫「常态」，或用具体的服装/外观命名（如「常态·白裙」）。

剧本没有写明换装时，默认沿用上一个状态。跨集出现时也一样：没有换装描写就沿用，不要凭空新增状态。

### 合理推断的边界

- **拆出新状态必须有原文中的换装或持续性外观变化依据**；场景用途、剧情类型和设计常识不能替代这一依据。每个资产的初始常态以首次出现的原文为依据，未写明的造型细节标注待确认。
- 合理推断只用于补充已有资产或已有状态的视觉细节，例如年龄范围、服装材质。必须在 `note` 中注明具体推断内容、依据及适用范围；无法合理判断的细节写「剧本未说明，待设计确认」。要求描述完整，不代表可以把未知细节当成原文明示。
- 已有原文明确描写的造型或布置，在后续没有变化描写时可以延续。例如大厅第一次写明烛火和柱子，后续沿用该常态即可，无需新增状态。
- 不得用合理推断新增原文未出现的资产或关键陈设，例如只写「黑曜大厅」不能补出「龙骨王座」。

### 凭直觉觉得"该有"但原文没写的状态，不能编

常见情况：某类场景按经验/常理通常会有专属造型（国王坐朝该穿龙袍、角色在卧室该穿睡袍、下雨该披雨衣），但这一版剧本的动作行里**没有任何文字描写**这个人物换了装。这时无论多符合直觉，都不能凭空加一个状态——核心规则第一条写得很清楚：**状态永远是先有原文依据，再有状态**。

正确做法：

1. 把这个人物在这类场景里的全部相关场次找出来，逐场确认动作行是否真的没写换装
2. 确认没写之后，按常态处理（沿用当前状态，不新增）
3. 在常态状态的 `note` 里记一句话，说明"剧本在 XX 类场次均未描写换装，按常态处理，如需要专属造型需美术或编剧另行确认"，并列出具体场次号
4. 汇报时把这条 note 提一下，交给用户或后续环节判断是否要让编剧/美术补一版设计——**这是创作补充的决定，不是提取环节该擅自做的事**

判断"原文到底有没有写"时要注意：别把场景道具（王座）、场景陈设误认成人物的服装变化；也别把"情绪/眼神描写"（金瞳翻涌龙焰）当成外观造型变化，这些在前面章节已经讲过，不要在这里重新引入。

### 状态描述的详细程度规则

**核心原则**：状态描述必须包含该状态下的**完整视觉特征**，足够让美术和服化道团队直接设计制作，不需要回查基础设定。

#### 人物状态描述必须包含（按优先级）：

1. **基础生理特征**（每个状态都要重复）

   - 年龄（约X岁）
   - 体型身材（高矮胖瘦，具体身高区间）
   - 种族（人族/龙族/精灵/狮族/狐族等）及种族特征（竖瞳/尖耳/兽瞳等）
2. **头发**（最显眼）

   - 发色（银白/黑色/金色/深紫等，含光泽度）
   - 发型（散落/束起/盘髻，具体到高低、层次）
   - 发饰（发簪/发带/无，材质和样式）
3. **面部**

   - 眼睛（瞳色、眼神、特殊形态如竖瞳）
   - 五官特征（精致/刚毅/平凡）
   - 妆容（有/无，具体到眼妆唇妆）
   - 肤色（苍白/古铜/健康/冷白等）
   - 特殊标记（咒纹/龙纹/伤疤等的位置和状态）
4. **服装**（最复杂）

   - 主体服装（长裙/长袍/战甲，颜色、款式、材质）
   - 细节（领口/袖口/裙摆，收紧或宽松，长度）
   - 腰部处理（束腰/宽松/腰带样式）
   - 外搭（披肩/披风/外套，材质和固定方式）
   - 特殊元素（刺绣图案位置和主题、破损染血位置）
5. **配饰**（从上到下）

   - 头饰（王冠/头巾/无）
   - 颈部（项链/围巾/纱布包扎）
   - 手部（手套/戒指/武器）
   - 腰部（腰带/腰挂/小袋）
   - 足部（靴子/布鞋/赤脚，材质和高度）
6. **整体气质**（最后一句总结）

   - 威严/柔弱/凶悍/优雅/颓废等

**禁止事项**：

- ❌ 状态描述不能只重复基础设定（如只写"年龄20岁，狐族"）
- ❌ 不能只写变化点而省略其他部分（如只写"白裙染血"，头发、面容、配饰呢？）
- ❌ 不能假设读者会"参照基础设定"，每个状态必须独立完整

**`note` 字段使用规范**：

**仅在以下情况使用 `note`（需要人工确认的不确定内容）**：

✅ **应该写入 `note` 的内容**：
- 描述中包含了原文没有明确写、是合理推断出来的视觉细节（如年龄范围、材质、尺寸），需注明具体推断内容、依据及适用范围
- 剧本未明确描写但按常理可能需要专属造型的场次（如"剧本在卧室场景均未描写睡袍，按常态处理，如需专属造型需美术确认：场次8-3, 12-1"）
- 疑似同一道具但名称不一致的情况（如"疑似与「龙骨匕首」为同一件，需编剧确认"）
- 无法从原文判断的细节（如"剧本未说明材质，待设计确认"）

❌ **不应该写入 `note` 的内容**：
- 提取过程记录（如"这是特效不拆状态"、"已按规则判断"、"使节1有台词，因此归类为配角而非群演"）—— 这些是你的判断过程，应该体现在结果本身（拆/不拆状态、角色分类），不需要解释
- 已经明确的信息（如"此状态在第3集出现"—— 已在 `scenes` 字段体现）
- 你能够自主判断的内容（如角色分类、是否拆状态、场次归属等）

**核心原则**：`note` 只写**需要人工确认的不确定内容**，不写你已经做出判断的过程说明

#### 群演状态描述规则

群演的「常态」状态描述 = 群演基础设定的详细展开，需包含：

- 人数（约X人，或X-Y人）
- 每个人/每类人的完整外观（参照上述人物描述要素）
- 个体差异点（领头/年长/年轻，装备或服饰的区别）

#### 场景和道具状态描述

- **场景状态**：描述该状态下场景的视觉变化（破损位置、烧毁程度、装饰变化）
- **道具状态**：描述该状态下道具的外观（材质、颜色、尺寸、破损/染血位置）

**示例对比**：

❌ **错误**（过于简化）：

```
莱拉 S01 常态·白裙
description: "白裙，苍白，肩颈咒纹"
```

✅ **正确**（完整描述）：

```
莱拉 S01 常态·白裙
description: "年龄约20岁，纤细身形（约1.6米）。银白色长发（发质柔顺，光泽度高）自然散落至腰际，无任何发饰。琥珀色狐瞳（竖瞳），眼神怯弱。五官清秀，肤色苍白无血色。肩颈处暗红色血焰咒纹若隐若现（非完全显现）。身着白色长裙（简洁无饰，布料轻薄略透，及踝），无腰带无刺绣。赤脚。无任何配饰。整体气质虚弱、脆弱"
```

### 动作原文 vs 外观描述：不能直接摘录拼接

`description` 要写的是"这个人/这个场景/这个道具长什么样"，不是"这一场发生了什么事"。原文的动作行是叙事性的，混杂了情节、动作、心理活动；写 description 之前要先从动作行里**筛出外观相关的词**，剔除情节推进的部分，再按本节的要素清单组织成完整描述。把动作行原句摘录拼接起来，不叫提炼，只是换了个字段名重复一遍剧情。

❌ **错误**（把动作原文直接拼接当描述）：

```
吴耐 S01 62岁老年状态
description: "吴耐缓缓走上台，接过大大的奖杯。；吴耐有些虚弱看向台下的欢呼。；吴耐说着出现耳鸣，随后眼前一黑，直接倒下。"
```

这段文字告诉美术的是"发生了什么"，没告诉美术"长什么样"——没有年龄体型、没有服装、没有发型面容，美术拿到这个没法画人设。

✅ **正确**（从动作行里提炼出外观信息，缺失的部分合理推断并标注 `note`）：

```
吴耐 S01 62岁老年状态
description: "年龄约62岁，身形佝偻偏瘦，行动略显迟缓。头发灰白稀疏，面容苍老憔悴，眼神浑浊中带着虚弱感。身着老年人常见的朴素穿着（具体款式剧本未描写，按角色经济条件推断为洗旧的居家便装）。整体气质：病弱、邋遢，与场面的热闹气氛形成反差"
note: "服装具体款式剧本未明确描写，按角色设定（省吃俭用的拆迁户）推断为朴素居家装，待美术确认"
```

同一条规则也适用于场景和道具：场景 description 写的是"这个空间看起来是什么样"（材质、布局、陈设），不是"这场戏在这里发生了什么"；道具 description 写的是"这个物件长什么样"（材质、颜色、尺寸、外观变化），不是"谁用它做了什么"。判断方法：写完一条 description，读一遍问自己"去掉所有人物动作和对话，这句话还剩下可供美术直接设计的视觉信息吗？"如果去掉动作就所剩无几，说明还在复述剧情，要重写。

## 三、合并与命名

### 场景的层级结构

场景采用**主场景 + 子场景**的层级结构：

**主场景**：需要美术搭建的完整空间，如「黑曜大厅」「西塔」「龙木森林」
**子场景**：主场景内的不同区域或视角，共享主场景搭建

判断标准：

- **作为子场景**：视觉上和主空间连在一起，能共用一套搭建的不同区域
  - 示例：「黑曜大厅侧廊」是「黑曜大厅」的子场景
  - 示例：「西塔书房门口」是「西塔书房」的子场景（如果门口和书房内能共用搭建）
- **独立主场景**：需要完全单独设计和搭建的空间
  - 示例：「黑曜大厅」和「西塔书房」是两个独立主场景

**命名规则**：

- 主场景名：最常用的简称（「黑曜大厅」优于「暴风尖塔王宫黑曜大厅」）
- 子场景名：在主场景基础上加区域（「黑曜大厅·侧廊」）
- 剧本中的全称和简称：写进 `aliases`

**`int_ext`/`times` 在主场景层级必填，别漏写**：建主子场景结构时最容易只顾着填 `subscenes` 和 `description`，漏了主场景本身的 `int_ext`（内/外）和 `times`（时间），导致 Excel 里这两列整行是空的。这两个字段要从该主场景下所有子场景实际出现场次的原文内/外、时间汇总得到——如果不同子场景的时间不一样（比如白天去的猎场、黄昏才到的森林深处），`times` 要把两个值都列出来，不能只写一个。`--check` 会校验这两个字段是否存在，缺失时会报错。

### 其他资产

- **人物**：同一个人的不同称谓（「龙王」「陛下」「凯尔」）合并。人物行里写的名字必须出现在 `name` 或 `aliases` 中，否则校验会报警告
- **道具**：名称不一致但可能是同一件（「屠龙匕首」与「龙骨匕首」），不要自行合并，分开记录，可在独立的疑问记录文件中标注

## 四、ID 规则

- 人物 `CHR-001`，场景 `SCN-001`，道具 `PRP-001`，按首次出场顺序编号
- 状态 ID 写 `S01`、`S02`（导出时会拼成 `CHR-001-S01`）

## 五、Excel 输出格式

生成的 Excel 表包含 4 个 sheet：**人物**、**场景**、**道具**、**场次总表**。

### 资产表（人物/场景/道具）格式

每个资产占多行，资产基础信息（资产ID、名称、别名、角色类型/内外/归属、基础设定）**合并单元格**，每个状态占一行：

| 资产ID  | 人物名 | 别名/称谓 | 角色类型 | 基础设定                     | 状态ID      | 状态名     | 状态描述               | 出现场次      | 原文依据            | 备注                                     |
| ------- | ------ | --------- | -------- | ---------------------------- | ----------- | ---------- | ---------------------- | ------------- | ------------------- | ---------------------------------------- |

## 六、描述的精细度要求

### 基础设定（资产的固定特征）

这是资产的"底色"，贯穿所有状态。要写得足够详细，让美术拿到后能开始设计。

**人物基础设定**应包含：

- 体态身形（高挑/纤细/魁梧）
- 肤色、五官特征
- 发色、发质、标志性发型
- 眼睛颜色和特征（竖瞳、狐瞳等）
- 永久性标记（咒纹、疤痕、纹身的位置和颜色）
- 种族特征（狐耳、龙角的默认状态）
- 气质（冷峻/温柔/危险等，一两个词）

**场景基础设定**应包含：

- 空间尺度（大殿/小室）
- 主要材质（黑曜石/大理石/木质）
- 关键陈设和布局（王座位置、柱子、窗户、浴池等）
- 标志性装饰或氛围（龙旗、火盆、彩窗）

**道具基础设定**应包含：

- 材质和颜色
- 尺寸或形态
- 特殊标记或图案（血焰纹、狮纹、龙骨）
- 功能说明（若非显而易见）

### 状态描述（这一状态下的完整造型）

这是美术实际要画/制作的那一版。要写到**视觉上能区分的所有细节**。

**人物状态描述要包含的具体要素**，见第二节「状态描述的详细程度规则」里的完整清单（基础生理特征、头发、面部、服装、配饰、整体气质 6 大类，每个状态都要独立完整写一遍，不能只写变化点）——这里不重复列，避免两处清单维护出不一致。

**场景状态描述**应包含：

- 当前布置的改变（婚礼装饰、战后破坏）
- 特殊摆设（桌上放着什么、地毯颜色）

**道具状态描述**应包含：

- 损坏的具体部位和形态（"折断""碎裂""沾血"）
- 颜色或材质的改变

## 七、JSON 数据格式完整示例

```json
{
  "characters": [
    {
      "id": "CHR-001",
      "name": "莱拉",
      "aliases": ["狐女"],
      "role": "主角",
      "description": "狐族后代，琥珀色眼瞳，肩颈有暗红血焰咒纹",
      "note": "",
      "states": [
        {
          "id": "S01",
          "name": "常态·白裙",
          "description": "白裙，面色苍白，肩颈咒纹若隐若现",
          "scenes": ["1-1", "2-1"],
          "evidence": "1-1：莱拉身穿白裙，面色苍白，肩颈处的暗红咒纹若隐若现",
          "note": ""
        }
      ]
    }
  ],
  "scenes": [
    {
      "id": "SCN-001", "name": "黑曜大厅", "aliases": ["暴风尖塔王宫黑曜大厅"],
      "int_ext": "内", "times": ["夜"],
      "description": "黑曜石王座大殿，火盆、烛火、暗红地毯",
      "states": [{"id": "S01", "name": "常态", "description": "", "scenes": ["1-1"], "evidence": "", "note": ""}]
    }
  ],
  "props": [
    {
      "id": "PRP-001", "name": "屠龙匕首", "aliases": [], "owner": "凯尔",
      "description": "银黑色刀身", "note": "疑似与「龙骨匕首」为同一件",
      "states": [{"id": "S01", "name": "常态", "description": "", "scenes": ["3-1"], "evidence": "3-1：罗恩爵士递上屠龙匕首", "note": ""}]
    }
  ]
}
```

字段说明：

- `role`（人物）：主角 / 主要配角 / 配角 / 群演
  - **主角**：剧情核心人物，贯穿全剧
  - **主要配角**：有独立剧情线、多次出场、对主线有重要影响的角色
  - **配角**：有明确角色设定、**有台词**、或虽无台词但有关键剧情作用的角色
  - **群演**：**无台词**且有连续性出场的群体性角色（如守卫、侍女、宾客等）
  - **判定重点**：凡是在剧本中有台词（对白）的角色，无论出场次数多少、是否为群体性角色（如"侍从1"、"使节1"），都必须归类为**配角**，不能归为群演
- `int_ext`、`times`（场景）：汇总该场景所有场次的内外和时间
- `owner`（道具）：主要使用者，没有就留空
- `evidence`：写场次号加原文短句，是新状态的就写触发换装或变化的那一句
- `scenes`：该状态出现的全部场次号，必须是 scenes.json 里真实存在的场次

## 八、场景层级结构示例（续七，补充 subscenes 字段用法）

```json
{
  "scenes": [
    {
      "id": "SCN-001",
      "name": "黑曜大厅",
      "aliases": ["暴风尖塔王宫黑曜大厅"],
      "int_ext": "内",
      "times": ["夜"],
      "description": "黑曜石王座大殿，火盆，烛火，暗红地毯，黑曜王座",
      "note": "",
      "subscenes": [
        {
          "name": "主厅",
          "description": "大厅主空间，王座区域",
          "scenes": ["1-1", "2-1"]
        },
        {
          "name": "侧廊",
          "description": "大厅侧面的廊道，龙骨烛台",
          "scenes": ["4-1"]
        }
      ],
      "states": [
        {
          "id": "S01",
          "name": "常态",
          "description": "",
          "scenes": ["1-1", "2-1", "4-1"],
          "evidence": "",
          "note": ""
        }
      ]
    }
  ]
}
```

**字段说明**：

- `subscenes`: 可选字段，主场景下的子场景列表
- 每个子场景包含：
  - `name`: 子场景名称（如"主厅""侧廊""门口"）
  - `description`: 子场景的具体描述
  - `scenes`: 该子场景对应的场次号列表
- 所有子场景的 scenes 加起来应该等于主场景 states 里的 scenes
- 如果主场景没有明显的子区域划分，`subscenes` 可以省略或为空数组
