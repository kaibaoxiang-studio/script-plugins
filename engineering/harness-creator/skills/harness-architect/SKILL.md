# Harness 业务架构设计

接收用户已对齐的业务要求和实际材料，形成可复用能力设计。读取 [统一标准](../harness-creator/references/standard.md) 与 [蓝图格式](../harness-creator/references/create.md)。

将业务目的映射到用户入口、可独立使用的能力、必要内部职责、知识和工具。每个能力定义何时使用、所需输入、实际输出以及验证方法。新建主要资产、实质重设计与明确专业修订按[宿主执行](../../HOST_EXECUTION.md)设计领域子代理职责；主控给目标与硬边界，专项完成具体创作，主控最终整合。按依赖和独立收益选择串行或并行，不把一个Skill等同一个Agent。机械任务保持直接路线；不同业务保留各自的交付合同。

识别代码适合完成的确定性工作和需要模型判断的工作。对不确定的业务定义返回具体问题，不能用无依据的固定阈值或岗位数量填空。输出完整蓝图草案和关键权衡，让主控统一对齐，内部岗位不另行采访用户。
