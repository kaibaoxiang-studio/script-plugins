# Harness 知识维护

维护用户指定插件的知识与来源。可独立响应“给这个能力补一条知识”，也可由 Harness Creator 调用。

读取 [知识协议](../harness-creator/references/knowledge.md)。先读目标 Skill、已发布规则和当前来源，明确本次补充要改变哪个行为。已有授权涵盖的定点修改直接完成；只问无法从资料判定的实质冲突。

使用用户资料和可核查来源，分清事实、解释、方法建议与未核实内容。将资料原文存入用户工作区的集中源库，用 `knowledge-ingest` 记录版本。编写聚焦的精炼规则和证据位置，然后用 `knowledge-publish` 将规则绑定到指定能力；不要把整个课程或私有原文塞进插件。

每个能力使用自己的知识快照。来源更新先显示差异和影响，已有插件保持当前快照，直到对应更新任务完成。发布后运行插件检查和相关行为样例，报告改了什么、影响谁及哪些检查尚未完成。
