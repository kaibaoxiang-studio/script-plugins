# 验证与交付

验证与声明保持一致。测试报告分为结构检查、确定性代码/调度检查、真实 Codex 最小调用和业务样例，每项保留触发方式和结果文件。

1. 运行 doctor，核对 Python 3.12+、锁定依赖、Codex CLI 和包结构。不能用修改 Codex 配置处理兼容失败。
2. 运行 validate，检查 manifest、Skill、references、脚本语法、接口及 DAG。输入输出 JSON Schema 使用完整 Draft 2020-12 本地校验，引用限制为本地 $ref。
3. 执行实际脚本与合成样例。根据变化选择有意义的断言：内容完整、计算正确、来源可追溯、产物存在、错误受控。不要只比较措辞或函数名。
4. 首次建设 runtime 时检查顺序、并行、失败重试、取消、中断恢复、事件重放、来源变化和无效产物。
5. 用真实 App Server 调用目标 Skill 检查加载、结果和文件。大业务项目另行验收；一个通信测试只证明该次调用成功。
6. 打包后解压到独立目录再验证。生成插件不读取开发机绝对路径，不需要安装 Creator。列出已通过、失败与未执行事项，再交付 ZIP 和源码。

外部整合需要检查源文件哈希、许可证、实际改造和行为。知识更新需要检查指定能力的加载关系及无关快照保持原状。增量修改需要覆盖用户编辑冲突和目标版本。

修正应针对具体失败。一个检查通过后不无依据扩大测试；出现新修改或仍有具体风险时再补相应检查。
