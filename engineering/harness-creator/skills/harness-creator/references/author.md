# Skill 编写与修改

每个 Skill 只承担能清楚描述的用户目标或内部职责。name 使用小写字母、数字和连字符，description 写用途与触发条件；正文说明会改变模型决策的业务方法。默认正常发现，用户要求明确调用的入口在 agents/openai.yaml 设置 allow_implicit_invocation: false。

保持渐进加载：正文放共同目的和关键规则，references 放条件性知识，scripts 放可重复的确定性操作，assets 放用于输出的模板。不要为每个新 Skill 建立没有用途的目录，也不把通用教程和同一条规则复制多份。

生成能力应可在目标插件独立运行。引用的工具或依赖必须实际可用；缺失时说明需要的接入和真实状态。运行环境使用相对路径和明确固定依赖，源库与运行数据在用户工作区。

修改时阅读已有内容，沿用户要求做增量变化。固定步骤、确认门槛和失败重试的严格程度应与实际任务相称。不要把某个案例、失败或创作偏好升格为所有业务的硬规则。

Python 脚本需要真实输入、确定的输出协议和必要的失败处理；运行它来验证业务行为。说明文字、空函数或模拟测试不能证明实现完成。构建后使用 bundled validate 检查格式，用代表请求检查触发和实际输出。

本协议参考 OpenAI Skill Creator（Apache-2.0）及官方 Agent Skills 文档；原许可随包保留。
