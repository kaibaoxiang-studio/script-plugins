# 宿主原生专业委派

默认使用当前宿主的原生子代理工具，由主控规划、委派、等待实际返回并整合。Python Harness不能直接调用宿主工具，不提供自动native桥，也不通过普通聊天线程模拟专业岗位。子代理可在宿主活动视图被查看，不保证任何界面都不显示线程。

主控先确定业务读法、视觉目标或语义任务、事实与批准边界，专业子代理负责具体设计；主控不要先把完整答案写死后只让专项润色。一个子代理可联合使用多个Skill和reference。按当前领域与问题分组，不按每个文件/每个维度开Agent。

新建主要资产、实质重设计或明确专业修订优先委派；成熟稿整理、格式修正、已有成果导表等机械工作直接执行。没有原生工具时说明未执行的工作；允许的简单任务可透明由主控完成，独立验收保持待验，不能声称已会诊。

任务给出对象/阶段、有关原文或当前稿、目标问题、保持项、允许改动、准确Skill路径及需要的正文。只加载有关知识，不把整个聊天历史或知识库复制给所有人。子代理读取资料后交可直接采用的设计/分析正文及真正影响整合的冲突。无必要不另落文件，需落盘时只写各自草稿；主控是最终文档的唯一写入者。

有依赖先等待上游，独立任务按宿主实际容量并行。已作为专业子代理收到任务时，直接使用所选Skill完成，不为执行同一任务再委派一层；只有真正独立的复杂子问题才考虑追加协作。不额外采访用户，不默认多方向、逐专项报告、层层再分派或循环会诊。保留每个业务原有的语言、候选数量、图片版式及批准规则；角色的单方向偏好不扩散为所有领域规则。失败返回真实状态，不能把方法标签或任务ID当作设计完成。

Python脚本仍处理解析、校验、保存、版本与导出。已有Engine自定义executor接口保持可用，但只是Python回调，不是原生子代理桥。

## 独立CLI兼容

旧蓝图仍接受kind=python或agent。CLI默认agent-backend=host：遇到Agent节点明确报告未执行，不启动App Server；Python-only任务照常运行。只有明确要求独立CLI兼容调用时才传 --agent-backend appserver。该分支每次新建ephemeral:true并核对服务确认，旧thread_id只作诊断，不resume持久聊天；服务不支持临时会话即失败，不退回普通聊天。旧业务文件、来源和批准不迁移；失败的兼容运行按原规则另建任务，不改旧记录。

当前机制不保证设计审美或节省token。依实际返回、合稿保持项和失败行为验证，不以调用数或篇幅代替效果。
