## 建议的手动测试顺序

1. 在新聊天中明确调用 `$harness-creator`，要求先通过 Grill Me 对齐一个小能力，再生成完整插件；检查它是否遵守已确认决定。
2. 给定一个有许可证的外部 Skill，要求列出拟采用内容后转换；检查来源、版本、许可和可用代码。
3. 用 `$harness-knowledge-maintainer` 为指定能力补一条规则；检查只影响目标能力，且实际引用已更新。
4. 修改一个已生成文件，再让 Creator 升级插件；检查保留内容与冲突提示。
5. 通过 Creator 重新对齐“剧本标准化→场记→资产／节拍”，用真实业务材料验收。

真实调用排查时，优先从无中文路径的工作目录复现当前 CLI 的问题；这是本次观察到的环境问题线索，尚未验证该规避办法有效。失败时保留 `.harness` 中的任务报告与错误，供后续修复。

源码中的 tests 为后续维护保留。需要时运行 `python -m unittest discover -s tests -v`，本交付不将尚未执行的用例视为通过。
