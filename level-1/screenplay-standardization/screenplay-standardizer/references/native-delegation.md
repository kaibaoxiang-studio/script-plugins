# 全段语义处理与原生子代理

## 正常宿主入口

主控从用户已给文件与目录取得 source_path、artifact_dir、input_kind 和 review_mode，保留已确认选择，不要求填写新的输入表。先按能力 Skill 用本包锁定 Python 执行解析；Python 只处理结构、定位、确定性检查、保存与导出，不代替语义标准化／创作。普通聊天不通过 App Server／新建普通聊天派发；独立命令行 Harness 仅作为用户明确采用的兼容入口。

## 语义工作如何分配

- 标准化、细纲创作或深审按连续集／场段交给宿主原生子代理；短稿可单个任务，长稿分连续段。不要按标题、动作、对白或导演身份拆为多个代理。每段任务含完整原段及可定位来源、相邻衔接上下文、已确认姓名／时间线约束、当前阶段、输出要求，以及对应本包 Skill 与参考绝对路径。任务覆盖范围必须无遗漏，不能用摘要、资产表或关键词命中代替全文阅读。
- 子代理实际读本包规范和所分配完整原文，返回该段可合并的标准化／创作结果、title／summary、来源标记与具体疑点；只审查时仅返回有原文证据的问题，不改正文。独立审查者自行比对来源与当前稿，不能只复述作者的判断。
- 主控维护全稿阅读范围，唯一合并 work.json，统一姓名、集场连续编号、跨段指代、剧情因果、人物知识及持续状态，复核段界衔接；已读每段不等于已经完成跨段综合。禁止子代理各自 finalize、改共用 work.json 或并行写最终文件；需要文件时仅隔离草稿。默认 light 不扩成全稿多岗位深审，deep 仍须用户选择并实际完成。
- 解析、格式转换、成熟结果的保真写入和导出直接运行 Python；主控只执行当前必要步骤，沿用四个标准化交付／两个审查交付，不新增内部会诊表为用户交付。
- 本 Skill 已作为子代理任务时，直接完成所分配语义工作，不递归派发。宿主无原生子代理或调用失败时，说明协作未执行；可以由当前主控完成并标明实际方式，不能冒称独立审查完成。必要的独立审查未执行须作为未完成项报告。
